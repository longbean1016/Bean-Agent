# 流式存储性能回归与兼容

在仓库根目录运行 `.venv/Scripts/python.exe -m tests.performance.benchmark_stream_store`。
基准只建立临时数据库，分别注入 0、20,000、40,000 条旧格式分片，追加相同的 60 条分片，输出落库耗时中位数、P95 和总耗时；不包含网络、模型生成或页面渲染时间。功能断言位于 `tests/unit/session/test_stream_store.py` 和 `test_chunk_index.py`。

跨测试目录运行时使用 `.venv/Scripts/python.exe -m pytest --import-mode=importlib tests/unit -q`，避免不同目录中的同名 `test_store.py` 发生导入冲突。

## 格式与写入规则

- 新分片直接追加到已有 `session_events`，每行一个逻辑事件，不重写历史行；单次序列化规模仅取决于当前传入载荷，没有累积成员或累积字节的增长。
- 取舍：物理事件行数与索引空间会增加，换取稳定的追加开销；不是将分片变成页面聊天消息，语义消息仍按 Turn 保存。
- 旧 `session_chunk_rows` 原样保留。新增派生索引 `session_chunk_index_v1`，用于幂等键、共享事件序号和来源查询。首次初始化在独立事务中完成，失败全部回滚，重启可重试；后续启动不重复解析旧 JSON。
- 读取接口继续合并两种物理格式，Turn、消息和 tool_chain 不迁移。保存后推送的顺序不变。
- 兼容触发器在旧格式行被追加、改写或删除时维护索引。支持旧版通过现有读取器读取新单事件记录，但旧版会重新遇到性能瓶颈；不要同时运行不同版本的写入进程。遇到更早、不支持 `session_events` 的版本应恢复对应备份，不直接打开新库。

## 升级前备份与回退

1. 停止后端，确认没有正在生成的会话及其他数据库写入者。不要在真实运行库上跑上述基准或手工试验迁移。
2. 对实际工作目录中的 `sessions.db`、`model-settings.db` 各做一份带日期、互不覆盖的完整备份。推荐 SQLite `Connection.backup()`，它包含已提交 WAL 内容；若使用文件复制，必须先完成 WAL checkpoint 并关闭所有连接，不能只复制仍活动的主文件。
3. 先在备份副本验证可打开、`PRAGMA integrity_check` 为 `ok`，并核对会话、事件与消息数量，再启动新版。第一次打开会自动建立旧分片索引，模型资料也会用已有本地目录补全。
4. 若需回退，先停止后端，另行备份升级后新增数据；将升级前备份恢复到独立目录并把旧版指向该目录，核实后再切换。不要覆盖唯一的新库，也不要把旧备份与新库的 WAL/SHM 混用。

自动测试使用临时库验证 SQLite backup、首次索引建立、失败回滚、重启不重复建立和从备份读取；不会自动备份或修改用户真实数据库。

## 模型请求输出预算

公共目录的 `limit.output` 表示能力上限，不会把默认 8192 请求预算提升至数十万。没有手动输出覆盖时，以启动配置的请求预算为基准，并受已知输出上限和上下文窗口约束；有效的手动输出覆盖优先。容量的手动覆盖（包括显式空值）在目录刷新后保留，活跃请求继续使用已冻结资料，后续请求按模型 revision 创建新实例。

手动输出预算若大于等于已知上下文窗口，会明确报错，不静默改写用户值。手动清空上下文容量保留为未知，不用运行时快照覆盖；缺失覆盖字段则照常按目录或既有本地解析机制处理。
